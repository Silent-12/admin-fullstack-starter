# 注释风格

[返回规则入口](../../AGENTS.md)。本文中的源码路径均相对 `backend/` 目录。

适用于 `src/**/*.ts` 中新增或修改的类、Controller、Service、公共方法、复杂逻辑与其他注释，以及 `test/`、`test-integration/` 与根目录脚本中的注释；`.d.ts` 类型声明及其字段注释遵循根目录 [TypeDoc 技能](../../../.agents/skills/typedoc-style/SKILL.md)。可参考实现：`src/modules/auth/admin/admin-auth.controller.ts`。规则引入前已存在的文件已按本规则完成一次全量收敛，后续修改不得回退到旧格式。

## JSDoc 块格式

类、Controller、Service、公共方法与复杂逻辑统一使用多行 `/** */` JSDoc，禁止写成 `/** 标题 */` 或 `/** @description … */` 单行形式。`/**` 与 `*/` 各自独占一行；`/**` 与紧随的装饰器或声明缩进对齐，块内每行以「缩进 + 空格 + `*` + 空格」开头：

```typescript
/**
 * 用户登录
 * @description 校验用户名与密码后签发访问令牌；触发限流时通过 `Retry-After` 响应头返回等待秒数
 * @param dto 登录参数
 * @param request HTTP 请求
 * @returns 登录结果，`data` 为访问令牌与过期时间
 */
```

- 标签顺序固定：标题 → `@description` → `@param` → `@returns` → `@throws`；块内与标签之间不留空行。
- 首行标题用一句话概括职责，行末不加句号；`@ApiOperation` 的 `summary` 同样不带句号（业务动作一致性要求见 [backend/AGENTS.md](../../AGENTS.md)）。
- `@description` 独占一行，说明业务职责、关键约束与容易误解的行为，不得只复述 HTTP 动词或参数校验；需要续行时另起 ` * ` 行继续，不折回标签行。`，代码标识符、路径和响应头使用反引号。
- 仅在存在参数时写 `@param`，按参数声明顺序逐行说明，格式为 `@param 名 说明`，不写 TS 类型、默认值与可选标记，行末不加句号。
- 仅在返回值需要说明时写 `@returns`，位于全部 `@param` 之后，行末不加句号；返回 `ApiResponseDto` 时说明 `data` 的含义。`void` / `Promise<void>` 等方法不写 `@returns`（包括「无返回值」），构造函数不写 `@returns`。
- 仅在方法会主动抛出异常且调用方需要处理时追加 `@throws 错误类型 触发条件`，位于 `@returns` 之后，行末不加句号。
- 仅注入依赖且无额外逻辑的构造函数可省略注释；需要说明注入依赖或构造行为时使用多行 JSDoc，并为每个参数写 `@param`。
- JSDoc 上方空一行；JSDoc 与紧随的装饰器或声明之间不留空行；装饰器连续书写，方法或类成员之间空一行。
- 禁止 `/** XXXX */` 等无业务含义的占位注释；`.ts` 文件中的字段、常量等简短说明可使用单行 `/** 说明 */`，行末不加句号；`.d.ts` 类型声明及其字段注释按根目录 TypeDoc 技能处理（字段使用 `//`）。

## 行注释

- 装饰器配置、无参数且逻辑简单的生命周期钩子、复杂分支与关键阶段使用紧邻的 `//` 行注释；带参数或复杂逻辑的生命周期钩子按公共方法使用多行 JSDoc；类或方法前不得再叠加与 JSDoc 重复的 `//` 标题注释。
- `AppModule` 模块导入注释按 [backend/AGENTS.md](../../AGENTS.md) 的「模块名标题行 + 普通说明行」格式执行：使用 `/** */` 块但不写 `@description` 标签，标题行与说明行均不加句号，每个模块导入前都必须有该注释，数组内相邻元素之间不留空行。
- 修改或删除已有注释时，保留仍然有效的内容；注释已失效、与实现不一致或产生误导时必须同步更新或删除。

## 其他注释类型

- **DTO 属性**：字段说明由 `@ApiProperty` / `@ApiPropertyOptional` 的 `description` 承载，不再重复写字段注释；`@Transform` 等装饰器行为不易理解时，在整条装饰器链上方用紧邻的 `//` 说明，不插入装饰器链中间。
- **TypeORM 实体字段**：在装饰器上方使用单行 `/** 说明 */`，说明业务含义、枚举取值与单位（如「0 未删除，1 已删除」「Unix 秒」）；仅解释列映射、`transformer` 等复杂机制时使用多行 JSDoc，并在 `@description` 中说明原因。新增实体必须逐字段补齐。
- **配置文件**：`src/config/*.config.ts` 的配置工厂与配置对象使用多行 JSDoc（标题 + `@description`），说明配置来源与开关语义；配置项含义以 `.env` / `.env.example` 为准，不逐项注释；校验辅助函数按普通函数注释。
- **私有状态、常量与局部类型**：Service、中间件内部私有字段仅当含义或取值来源不能从字段名直接判断时，在上方写一句 `//` 说明；字段、常量等简短说明使用单行 `/** 说明 */`，同一常量不得同时叠加多行 JSDoc 与单行 JSDoc；非 `.d.ts` 文件中仅内部使用的 `interface` / `type` 使用两行 JSDoc（首行说明 + `@description`），字段与外部库类型同构或语义自明时可不逐字段注释。
- **测试文件与脚本**：`test/**/*.mjs`、`test-integration/**/*.mjs` 不使用 JSDoc，仅在用例名无法表达 mock 状态、动态模块装配、时序模拟等意图时使用紧邻 `//` 说明，不重复 `test()` 名称；`*.config.mjs`、其他 `.mjs` 脚本使用 `//` 说明职责边界与关键取舍，不使用 JSDoc；Lua/SQL 等内嵌脚本使用脚本自身注释语法（如 `--`）标注步骤，外层常量或函数仍按 JSDoc 说明输入输出。
- **行尾注释**：配置对象中的简短说明允许使用行尾 `//`；较长说明改为上方独立 `//` 行。行尾注释不得代替类、方法或关键分支的注释。
- **枚举取值与标识符**：联合字面量类型、状态枚举等应在 `@description` 或单行注释中列出各取值含义（如「1 用户端，2 后台管理，3 Webhook」），不只描述类型用途；`@description` 以及 `@param`、`@returns`、`@throws` 的说明文本中提及的类型名、字段名、路径、响应头与装饰器统一使用反引号（`@param` 的参数名、`@throws` 的错误类型等标签语法成分除外）。
- **`.d.ts` 标点**：类型头首行简短说明不加句号，`@description` 行末不加句号；字段 `//` 注释不加句号且字段之间不留空行；匿名内联对象仅在父字段处说明整体含义。
