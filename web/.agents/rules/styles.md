# SCSS 与深色模式

> 作用域：`web/`（源码路径相对 `web/`）。规则入口：[web/AGENTS.md](../../AGENTS.md)。

## 样式入口

- 宿主样式统一使用 SCSS，入口为 `src/assets/styles/index.scss`，保留 `mixin.scss`、`reset.scss`、`el-ui.scss`、`el-light.scss`。
- 主题变量、暗色底座、布局与过渡动画由 `@ao/admin-layout/styles.css` 提供，在 `main.ts` 中先于宿主样式引入；禁止在宿主保留迁出样式的副本。
- 禁止引入 Tailwind 等原子化 CSS 框架；禁止使用内联 `style=""` 写大段样式（动态样式除外）。

## 组件样式命名

- Vue 组件使用 `<style scoped>` 时，每个组件只声明一个顶层模块 class 作为样式作用域入口，内部子节点使用简短且语义明确的命名；禁止机械重复大段 BEM 前缀。
- 布局类名优先使用 `left`、`right`、`top`、`bottom`、`header`、`body`、`footer`、`content`、`main`、`aside`、`actions`、`item`；信息展示类名优先使用 `info`、`title`、`description`、`label`、`value`、`text`、`icon`、`tip`。
- 仅在存在跨组件复用、全局覆盖、Element Plus 深度覆盖、多层状态表达或样式作用域不适合依赖 `scoped` 时，才使用完整 BEM 命名。

## 尺寸单位

- 后台界面以 `px` 为主要尺寸单位：控件高度、表格列宽、头像与图标尺寸、内外边距、布局间距、圆角、边框及动画位移默认使用 `px`；图标即使通过 `font-size` 控制大小，也按图形尺寸使用 `px`。
- `rem` 按需用于跟随根字号变化的文字字号；已有文字字号及其配套 `rem` 行高可保留，不要求将已有 `px` 字号统一改成 `rem`；新增文字行高优先使用无单位比例，用于固定高度控件垂直居中的行高跟随控件高度使用 `px` 或相同的尺寸变量。
- 自适应布局优先使用 Flex / Grid、百分比与最大最小尺寸约束，视口高度可使用 `vh` / `dvh`；不得按窗口宽度动态修改根字号整体缩放界面，也不得为单位换算强制设置根字号为 `16px`。
- 新增以视口宽度划分的固定布局断点默认使用 `px`；现有 `rem` 断点可保留；单位整理不得改变断点值；`39.99rem` / `47.99rem` 在默认 `16px` 字号下分别为 `639.84px` / `767.84px`，不得取整为 `640px` / `768px`。
- 单位迁移以浏览器默认根字号 `16px` 为等值基准，按 `1rem = 16px` 精确换算，保留负值与小数；不得将所有 `rem` 机械替换，也不得为统一行高改变实际行高；尺寸变量、模板静态尺寸参数、脚本中的样式默认值及相关注释、变量速查必须同步更新；只替换单位及等值数值，不得修改业务逻辑、公共 API、选择器、配色或动画行为。
- 单位迁移后必须比较修改前后的编译样式，确认默认根字号下的选择器、声明值与响应式断点等价；公共布局、组件包内的单位调整必须在对应包仓库维护并发版；禁止修改 `node_modules` 或在宿主复制、覆盖包样式。

## 样式整理

- 新增或重构的 Vue `<style scoped>` 组件优先整理为“一个顶层 class + 内部短语义 class”结构，再在该作用域内使用 SCSS 嵌套；仅在需要更强语义隔离或跨组件复用时保留 BEM。
- 同一 BEM 前缀的选择器必须使用 SCSS 嵌套，禁止重复书写完整类名。
- BEM 修饰符使用 `&--*`，BEM 子元素使用 `&__*`，连字符命名的子块使用 `&-*`；伪类、伪元素、状态类、直接子元素与媒体查询归属对应父选择器。
- 仅在编译后的 CSS 选择器与原选择器完全一致时才嵌套；禁止因嵌套新增后代层级或改变特异性；全局选择器、Element Plus 覆盖、动画、主题样式与跨组件覆盖必须保留原有作用域；必要时使用显式选择器（如 `& &__header`）保持原 CSS 语义。
- 不重命名现有 class，不改变声明数值、动画、层级与响应式断点；纯样式整理不得修改模板、脚本逻辑、接口、类型或公共 API；明确要求单位迁移时按「尺寸单位」执行等值换算，可同步修改模板静态尺寸参数与脚本样式默认值。
- 同一个声明区块内部禁止插入无意义空行；不同语义的选择器、注释、媒体查询与 `@keyframes` 区块之间可保留空行。
- 涉及样式重构时必须扫描全部 `.vue` 与 `.scss` 文件，确认 BEM 选择器已归并、声明区块内部无多余空行，并通过 Sass 编译或构建核对生成的 CSS 选择器。
- 无法映射到现有变量的业务专用颜色变量必须在宿主样式中以 `:root` 与 `.dark` 成对定义；公共主题变量在布局包仓库 `src/styles/theme.scss` 中维护并发版（安装产物只发布 `dist`，宿主以 `@ao/admin-layout/styles.css` 消费）；脚本配置、组件 props 默认值与主题变量定义中的颜色值不按样式声明处理，禁止将脚本配置颜色误改为 CSS 变量。
- 文本截断、溢出隐藏、多行省略等场景必须使用 `src/assets/styles/mixin.scss` 的 `@include ellipsis`，禁止手写 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` 重复代码；单行省略调用 `@include ellipsis`，多行省略调用 `@include ellipsis($rowCount)`（如 `@include ellipsis(3)`）。

## 深色模式

- 凡涉及颜色的样式（背景色、文字色、边框色、阴影色等）必须使用 CSS 变量，禁止硬编码色值（如 `#fff`、`#000`、`rgba(0,0,0,0.1)` 等）。
- 变量用途与当前值：见 [CSS 变量速查](../references/css-variables.md)。
- 新增或修改任何 `.vue` / `.scss` 文件时必须扫描 `<style>` / `<style scoped>` 块中的裸色值（`#fff`、`#ffffff`、`#000`、`#000000`、`#cccccc`、`rgba(0,0,0,...)`、`rgba(255,255,255,...)` 等）。
- 以下场景豁免：CSS 变量速查中已定义的变量定义代码本身（布局包仓库 `theme.scss`、`dark.scss` 中的 `:root` / `.dark` 块）；纯透明 `transparent`、`rgba(0,0,0,0)` 等无视觉影响的颜色；`box-shadow` 中确实需要固定不随主题变化的阴影，但必须在注释中说明原因。
- 检测到不符合条件的硬编码颜色时必须明确列出每个色值所在文件与行号，给出对照 CSS 变量速查的替换变量名；现有变量无法覆盖时按变量归属规则在 `:root` 与 `.dark` 中同时新增变量再引用。
- 检测到问题后直接输出警告与替换项并继续执行后续任务，禁止等待用户确认。

### 深色模式警告输出格式

```text
⚠ 深色模式适配警告：以下位置存在硬编码颜色值，暗色模式下可能出现显示异常：

1. `src/views/xxx/index.vue` 第 45 行 — `color: #333` → 替换为 `var(--ao-gray-900)`
2. `src/views/xxx/index.vue` 第 52 行 — `background: #f5f5f5` → 替换为 `var(--ao-gray-200)`
3. `src/views/xxx/style.scss` 第 10 行 — `border: 1px solid #ddd` → 替换为 `border: 1px solid var(--default-border);`
```

- 检查命令：见 [完成检查](workflow.md#完成检查)；样式整理必须执行其中的完整检查。
